# Review risk points & mitigations · 审核风险点

| # | Risk that could cause rejection | Mitigation in this kit |
|---|---|---|
| 1 | **Trademark / impersonation**: using "X"/"Twitter" or the X logo in the name or icon (policy: misleading or impersonating branding) | Name is `Follower Mosaic 粉丝拼图`, with no X/Twitter. The icon is a generic grid of dots, not the X glyph. "X" appears only descriptively, plus a "not affiliated with X Corp." disclaimer. The grid style's decorative X mark was removed. The **“X logo” style** (followers' avatars arranged in the shape of the X letter mark) ships in all builds by the developer's decision: it is one of four image styles, used descriptively to refer to the platform the followers come from, never as the extension's own brand, icon, name or promo tile. The listing says so and keeps the "not affiliated with X Corp." disclaimer. Residual risk: a reviewer may still ask to remove it; then drop the `xlogo` entry from `STYLES` in `extension/lib/common.js` and resubmit. |
| 2 | **Automated access / scraping of a third-party site** (X's ToS restricts automated collection; a reviewer may see it as a scraper) | It only runs after a user click, for one account at a time. It is read-only GET, 5 s + jitter per page by default (user-adjustable 1–10 s), 20 per page, a user-chosen cap (default 500, max 5,000), and it backs off on 429. It uses only the user's own session in their own tab. Nothing leaves the device, and there is no bulk export or upload feature. The listing frames it as a personal image generator, not a data tool. Residual risk: X can change or block the endpoints, and use is subject to X's terms (stated in the README). |
| 3 | **Undocumented/internal API + a hard-coded "Bearer" token** that looks like a leaked credential | The reviewer notes explain that the token is the public, constant one embedded in x.com's own web client for every visitor. It is not the developer's or the user's credential. Requests are same-site from the x.com page. Consider adding this sentence to the "Test instructions" or a reply to any reviewer query. |
| 4 | **Remote code** (MV3 forbids executing remote code) | Everything is packaged. There is no eval, `new Function` or remote `<script>` (audited). The queryId auto-discovery downloads X's JS as **text** and regex-reads an ID; it never executes it. This is declared in privacy-practices.md. |
| 5 | **Excessive permissions** (broad host permissions trigger in-depth review) | `activeTab`, `scripting`, `storage` plus host access to **x.com / twitter.com only** (1.0.1): a document_start capture script (so follower requests X made before the click, e.g. a cached Followers tab, are not missed) and a one-time resume after the panel's own reload fallback. Justified in privacy-practices.md. No `<all_urls>`, no pbs.twimg.com permission (avatars load via CORS). |
| 6 | **Undisclosed data handling / missing privacy policy** | Data usage boxes (PII, website content, auth info: conservative) are ticked with exact explanations, plus the 3 certifications. A standalone privacy-policy.html is ready for GitHub Pages. |
| 7 | **Third-party personal data in screenshots** (celebrity faces, brand logos) | Store assets use only synthetic, generated avatars (`store/synthetic/`). The `?demo=` screenshot mode and `demo/` assets are stripped from the store build. |
| 8 | **Single purpose unclear / keyword stuffing** | One purpose statement. Descriptions are plain, without repeated keywords or competitor names. |
| 9 | **Reviewer can't test** (needs an X login) | Test instructions are provided. The extension shows clear Chinese/English-agnostic screens when not on x.com or not logged in. Consider making the UI bilingual (currently Chinese-only); a mostly-Chinese UI under an English default listing is fine but may slow review. |
| 10 | **Functionality breaks after X changes queryIds/features** (a broken item can be taken down after a user report) | Automatic queryId discovery plus auto-added feature flags, and friendly "X updated, please update the extension" messaging. Plan to ship updates quickly. |
